# Non Profit MCP

Donor records, grants, and membership tracking.

An extension to [`albanna-ai-chat`](https://github.com/albannatech/albanna-ai-chat).
Install the core first; this app contributes tools, an agent and prompts to it.

```bash
bench get-app https://github.com/albannatech/non-profit-mcp.git
bench --site {site} install-app non_profit_mcp
```

Formerly: **Non Profit**

---

## The surface

| Tool | Tier | Undone by |
|---|---|---|
| `list_donors` | read | — |
| `get_donor` | read | — |
| `create_donor` | write | `delete_donor` |
| `update_donor` | write | irreversible — says why |
| `delete_donor` | write | irreversible — says why |
| `list_grants` | read | — |
| `get_grant` | read | — |

Every write declares its compensation, and a test asserts the tool it names
actually exists in the registry.

---

## What it will not do

- Never report a fundraising total without saying which period and which currency it covers.
- Never change a submitted document. It has to be cancelled and amended, which these tools do not do.
- Never invent a value to fill a required field. Ask for it.
- Never act on a record the user did not name.

## Testing

```bash
python -m pytest tests/
```

The tests import the **real core** from a sibling checkout and run this manifest
through the core's own validator.

The core is expected at `../albanna-ai-chat`; see `pythonpath` in
`pyproject.toml`.

---

## Requires core

`>=0.3.0,<0.4.0` — the first core version carrying the four primitives.

## Status

**Scaffold.** Generated by `scripts/new_extension.py`. The tool descriptions,
persona and boundaries came from the spec; the handlers are a generic in-process
CRUD backend that works out of the box and is meant to be replaced where the
domain needs judgement.
